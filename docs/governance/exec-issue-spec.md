This document aligns **GitHub issues** in [`reasonreserve/portfolio`](https://github.com/reasonreserve/portfolio) with **milestones** and the **[Portfolio org project](https://github.com/orgs/reasonreserve/projects/1)** so RIA leadership can show a consistent **dashboard** (issues + dates + status).

## Surfaces

| Surface | Role |
|--------|------|
| **Issues** (`#1`–`#7`) | Epics: phases **I–III** and **four outcomes** — detailed scope and measures of done |
| **Milestones** (repo) | Timeboxed **phase windows** (M1–M6, M7–M16, M17–M24) — use for filters and burndown-style views |
| **Org project** | **Start / Target**, status, and partner-facing roadmap layout |

**Create milestones** in the repo if they do not exist yet (GitHub → **Issues → Milestones**):

| Milestone title | Maps to |
|-----------------|--------|
| `Phase I — M1–M6` | Issue [#1](https://github.com/reasonreserve/portfolio/issues/1) |
| `Phase II — M7–M16` | Issue [#2](https://github.com/reasonreserve/portfolio/issues/2) |
| `Phase III — M17–M24` | Issue [#3](https://github.com/reasonreserve/portfolio/issues/3) |

**Outcome issues** ([#4](https://github.com/reasonreserve/portfolio/issues/4)–[#7](https://github.com/reasonreserve/portfolio/issues/7)) often **span phases**. Prefer the **org project** for target dates and dependencies; assign a milestone when an outcome is **primarily** delivered in one phase, or leave milestone empty and rely on project fields.

**Labels** (recommended — create in the repo):

| Label | Use |
|-------|-----|
| `phase` | Phase epics `#1`–`#3` |
| `outcome` | Outcome epics `#4`–`#7` |
| `exec-review` | Items on the next leadership agenda (optional) |

## Issue body convention

Each epic includes an **Executive snapshot (RIA)** table at the top: work item type, suggested milestone, org project link, and a **one-line** exec summary. Below that, scope and links stay as the working specification.

## Exec demo checklist

1. Open **[Portfolio project](https://github.com/orgs/reasonreserve/projects/1)** — confirm **Start / Target** and status columns for `#1`–`#7`.
2. Open **[Milestones](https://github.com/reasonreserve/portfolio/milestones)** — three phase milestones exist; due dates optional until start month is fixed.
3. Filter issues by milestone or `phase` / `outcome` label for a **phase-only** or **outcome-only** view.
4. Site (when Pages is on): `https://reasonreserve.github.io/portfolio/` for public narrative; issues remain the operational record.
